# AddonRay v1 contract and support matrix

## Status and authority

The user approved the private GitHub milestone [`v1.0.0`](https://github.com/ranokay/addonray/milestone/1) as the finite expanded v1 target on 2026-10-29. The milestone contains tickets #2 through #46. This document records the scope, support matrix, supersession map, release acceptance and exclusions from a dated snapshot read on 2026-10-29. It summarizes the actual ticket bodies and native `blocked_by` dependencies.

The snapshot is not a live mirror of the tracker. The GitHub milestone and its tickets remain authoritative, and native blockers are authoritative for start order. Recheck a ticket before starting it. A new ticket or a milestone change is a scope revision, not an implicit addition to this contract.

This contract records scope. #5 is answered by the dated saved-data contract linked below. It does not answer the decisions reserved to #4, #13 or #20. It does not authorize signing, publication, a license grant or a repository visibility change.

The implemented runtime is the inventory, comparison, timing, page-error and report-export work recorded in [status](status.md) and the dated [evidence](evidence/). No full-v1 implementation or qualification exists. Current session, one-pair, report and permission limits stay effective until a future contract is approved, recorded, its applicable feasibility gates pass and its implementation is qualified.

### Support states

| State       | Meaning                                                                                                                                   |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Intended    | The user approved the target, but v1 evidence is incomplete. It is not a support claim.                                                   |
| Qualified   | Evidence names the behavior, distribution, exact version, OS, architecture, test authority and observed result for the implemented slice. |
| Unqualified | No evidence exists, or the evidence covers another version, OS, architecture, distribution or slice.                                      |
| Excluded    | The target or behavior is outside v1 unless the user explicitly revises scope.                                                            |

## Supersession map

A backlog ticket is not a contract. Each future contract replaces a current limit only when all of these happen:

1. The user approves the contract named in the ticket, and it is recorded in the canonical documentation.
2. The applicable feasibility proof passes on the intended target.
3. The affected privacy, permission, architecture and evidence records are updated.
4. Implementation is qualified for the approved scope.

Existing runtime limits remain effective until then. A failed feasibility gate returns to a revised contract. It does not widen authority.

## Explicit exclusions

These exclusions are part of v1. Changing one needs an explicit user decision and a contract revision. The absence of an exclusion does not authorize a feature.

- No telemetry, analytics, cloud service, cloud report sharing, accounts or sync.
- No automatic modification of other extensions, global or per-site toggles, profile database edits, hidden policy changes or enterprise-policy claims.
- No causal culprit verdict, automatic ranking, score or diagnosis. AddonRay reports observations, user assessments and comparisons with their limits.
- No cross-extension console feed. No raw page content, URL, title, request detail, credential, cookie, token, error payload, stack or absolute timestamp enters a report beyond an approved bounded field.
- No continuous background recording. Collectors are explicit, bounded and separately consented.
- The companion is optional. It supplies one narrow allowlisted read-only operation, its own consent and no implicit browser authority. It never becomes required for inventory, capability explanations or extension-only inspection.
- No Edge, Safari, mobile or Manifest V2 target. Chrome for Testing and unsigned XPI loading are not retail qualification.
- No report import, HTML/PDF output or clipboard action before the #9 through #11 implementation and gates under the approved #5 contract. Bounded #6 save/list/reopen/delete, #7 retention/bulk-delete and #8 schema version 1 JSON export are implemented and locally qualified with explicit gaps.
- No publication, license grant or repository visibility change before #4 and the explicit approval for the concrete action.
- Chrome's page-side observer remains subject to page interference. AddonRay makes no tamper-proof observation claim.
